# 首次历史初始化与每日 T+1

在“数据集成 → 集成任务”新建或编辑 SQL T+1 任务，勾选“先初始化历史数据，再每日 T+1”，选择历史起始日期和按天/按月。选中初始化会同时开启后续每日调度，默认时间仍为 02:00、Asia/Shanghai。已有任务不会自动开启初始化。

## 区间与预览

首次保存初始化配置时，历史截止日期固定为配置时区当天，历史范围为 `[起始日期, 截止日期)`。起始日期可选 2000-01-01 至昨日；批次预览显示首批、末批及总批次。

按天为自然日；按月从实际起始日开始，到下月1日结束，最后一批截断到截止日。不会将月中选择的起始日期向前扩到月初。

例如 2026-11-13 保存、历史起始日为 2026-09-20、按月：

| 批次 | 起始（含） | 结束（不含） |
| --- | --- | --- |
| 1 | 2026-09-20 | 2026-10-01 |
| 2 | 2026-10-01 | 2026-11-01 |
| 3 | 2026-11-01 | 2026-11-13 |

历史补齐后，首个每日业务日期为 2026-11-13，对应 2026-11-14 02:00 执行。如果初始化耗时跨天，仍从这个业务日期依次追赶，直到接上正常日程。不会按初始化完成当天重设游标而跳过日期。

## SQL 写法

历史和日常使用同一份 SQL。推荐在 WHERE 中使用左闭右开的时间窗口：

```sql
SELECT VISIT_ID, DEPARTMENT_CODE, AMOUNT, UPDATED_AT
FROM QCRMYYCS.VISITS
WHERE UPDATED_AT >= TO_DATE(:window_start, 'YYYY-MM-DD HH24:MI:SS')
  AND UPDATED_AT < TO_DATE(:window_end, 'YYYY-MM-DD HH24:MI:SS')
```

按月必须同时使用 `:window_start`、`:window_end`，不能使用单日参数 `:biz_date`。按天兼容原来的单日参数。参数由服务端识别，字符串和注释中的同名文本不会被误认；参数外不再添加单引号。

平台不会替用户追加时间条件，SQL 必须实际按窗口过滤。日常建议使用业务系统正确维护的最后更新时间，才能采集历史记录后续发生的修改。带时区/UTC字段请显式转换，参见 [SQL T+1 日期参数说明](sql-t1-sync.md)。每个批次结果中的主键应唯一，按月时也要保证整个月结果满足这个条件。

## 断点、失败和暂停

详情显示已完成/总批次、已覆盖区间、当前或下一批区间、固定截止日和作业编号。只有引擎确认 FINISHED 的当前批次才推进断点，零行批次也会正常完成。

失败后先修复源数据、SQL 或连接凭据，再点击“继续初始化”。已完成批次保留，失败批次按原窗口重新执行；断点粒度为批次，不承诺批次内部的逐行恢复。未确认提交使用原作业编号核对，不直接分配第二个编号。

“暂停初始化”停止自动提交后续批次，当前批次继续运行；“停止”可以单独停止当前批次。暂停、继续是独立的状态操作，不需要源库连通。重新打开服务后继续读取持久化进度，运行记录只展示最近批次不会影响长期断点。

历史开始后，日期、批次单位、源/目标位置、采集模式、主键、映射和时区锁定；可以修复 SQL、名称和连接凭据。连接位置与范围也绑定到实际执行端点，避免暂停后改址使剩余批次来自另一套数据库。恢复原绑定位置后可继续。历史结束后不会因普通编辑再次初始化，每日调度可继续启停。

初始化期间不另开同任务的手动补数/日常运行，防止窗口交错。存在待处理每日批次的已有任务需先处理该批次再启用初始化。

## 合并与范围

继续使用 Doris 单列 UNIQUE KEY 主键合并：已有主键更新、新主键插入，本批缺少的旧行保留。不执行清表、分区覆盖或删除；失败批次重复写入仍按主键合并。使用受限只读源账号和已有权限体系。

服务端基于集群 Quartz、数据库版本 CAS、初始化 ID、批次编号、原作业编号及真实窗口结算进度。本轮测试和发布记录见 [历史初始化验证记录](sql-initialization-verification.md)。
