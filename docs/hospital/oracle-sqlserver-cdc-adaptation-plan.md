# Oracle 与 SQL Server CDC 适配方案

日期：2026-11-13。状态：用户已确认先完成 Oracle，SQL Server 分第二批；第一批进入实现。源库配置和源表写入按具体范围另行确认。

## 建设目标与分期

沿用现有 SeaTunnel 3.0.0、Doris 和 Integrate 登录，在当前数据中台增加可复用的 CDC 适配能力。优先完成 Oracle；SQL Server 沿用相同的任务、前置检查、字段映射和恢复机制，在第二批接入。

第一批范围：统一 CDC 适配接口、Oracle CDC 连接器与平台配置、Oracle 大表全量修复、CLOB/日期适配、前台前置检查及运行状态。第二批范围：SQL Server 2019 实机接入；SQL Server 2016 按补丁、版本类型及连接器兼容性单独验收。第一批不把 SQL Server 显示成已可用。

现有 PostgreSQL CDC、SQL T+1 和历史初始化保持兼容。全量、SQL T+1、CDC 使用各自的参数与恢复语义。

## 路线比较

| 路线 | 适用性与代价 |
| --- | --- |
| SeaTunnel 原生 Oracle-CDC / SqlServer-CDC → Doris（推荐） | 复用现有服务和调度，增加对应适配器及版本匹配的连接器，部署组件较少 |
| Debezium + Kafka → Doris | 适合未来多个订阅方共享变更事件、独立回放；当前会增加消息系统、连接器集群及其运维 |
| SQL 按水位定时查询 | 保留为源端无法满足 CDC 条件时的定时集成方式；需要可靠更新时间/变更表，不能承诺捕获任意删除，不作为实时 CDC 验收 |

## 平台与引擎改造

1. 将当前只生成 Postgres-CDC 的配置逻辑拆为数据库适配器。每个适配器负责版本规则、只读前置检查、参数构造、类型映射和恢复兼容性校验；平台统一任务状态、权限与运行记录。
2. Oracle 使用 Oracle-CDC。SQL Server 第二批使用 SqlServer-CDC。连接器与引擎均固定版本，校验下载摘要并检查依赖冲突，保留现有 Oracle NLS 驱动和检查点数据卷。
3. 数据源区分“程序已适配”“数据库前置条件满足”“当前任务可启动”。能力按当前实现计算，避免已保存的数据源因旧 supportedModes 永久看不到新能力；升级不重写用户密码或连接配置。
4. 新建任务默认使用连接器的“首次快照后持续增量”模式。通过同一 CDC 任务管理快照和日志衔接，不将独立 FULL 完成后启动 latest 当成无缝接续。
5. 首批沿用已实现的单列主键规则；无合适唯一键、多列主键或未验证类型明确提示原因并阻止启动，不宣称支持全部业务表。
6. Doris 目标使用 Unique Key，验证主键合并和 DELETE 传播。一个目标表只允许一条受控写入链路，避免多个任务交错覆盖。首批按表保持事件顺序。
7. 采用可恢复、允许重复投递的链路，依靠主键合并及删除重放实现最终收敛；不承诺未经验证的端到端 exactly-once 或跨表事务原子性。若以后启用 Doris 2PC，须单独验证事务恢复。

## 本轮全量问题的配套修复

- 修复 Oracle DATE 含时分秒的目标建表、元数据回读及类型兼容校验；不能将时间截成日期，也不能通过假改元数据绕过校验。
- 补齐 CLOB/NCLOB → Doris STRING。全量读取必须保留完整内容，覆盖中文、空串/NULL、超过 4,000 字符及超过目标长度限制的明确失败行为，禁止静默截断。
- CDC 大字段另外验证：完整快照、仅更新其他字段、更新大字段、NULL 切换以及恢复重放。不能将连接器“不可用值”占位符覆盖到目标业务字段。具体 Oracle 版本和连接器组合未通过这些用例前，该表不标记为完整 CDC 支持。
- 全量和 CDC 分别设置合理的读取分批、写入批量、检查点和超时，不继续对大表统一套用每批 100 行、5 秒间隔、60 秒超时。具体参数由隔离任务吞吐、内存、源库负载及恢复实测确定，单纯放大超时不作为修复验收。
- 进度区分累计处理量与实际目标数据量，展示快照阶段、增量阶段、检查点失败及恢复次数。避免将恢复后的累计读写数字当成唯一落盘行数。

## 前台操作

- 继续使用“数据源管理”“集成任务”两个独立菜单，PC 展示，新增和编辑使用右侧抽屉。
- 数据源提供“CDC 前置检查”，明确列出引擎连接器、实际版本、网络、日志/CDC 开关、权限、主键及目标表是否满足要求。
- 任务抽屉配置首次初始化、受控吞吐、字段映射和恢复；SQL T+1 配置保持独立。初版提供首次初始化及从有效检查点恢复，暂不开放任意手填日志位点跳过数据。
- 运行详情展示已确认的成功检查点、保存点和恢复状态。SCN/LSN 只有在引擎提供可靠已提交位点接口后才展示，不从日志文本推测提交进度。
- 源端建表或字段变化需停任务后重新校验和配置；首版不自动传播破坏性 DDL。

## Oracle 前置条件与当前限制

Oracle 路线采用 LogMiner。检查归档日志、数据库最小补充日志、目标表补充日志以及当前连接器实际要求的读取权限；日志保留应覆盖首次快照、停机和追赶时间。

SeaTunnel 文档列出 Oracle 11g、12c、19c、21c，但当前医院测试库为 **11.2.0.1.0**，这一具体补丁版本必须验证。Oracle 19c 的验证不能替代 11.2.0.1.0 的验证；SID/服务名和 CDB/PDB 配置按实际部署处理。

已检查的 HIS 测试库未开启归档模式及数据库级补充日志。可以先完成平台代码、连接器打包和只读前置检查；真实 CDC 验收需要 DBA 确定源库变更方案及窗口。平台不自行执行 shutdown、ALTER DATABASE、授权或源表 DML。

## SQL Server 后续适配边界

- SeaTunnel 3.0.0 的 SqlServer-CDC 文档以 SQL Server 2019 为列明版本。先以 2019 建立验收基线；2016 不能直接因数据库具备 CDC 功能就标为连接器已验证。
- 前置检查包括实际版本/补丁/版本类型、库级及表级 CDC、采集作业状态、SQL Server Agent、LSN 可用范围、保留时间和读取权限。
- Microsoft 文档说明 SQL Server 2016 SP1 扩展了 CDC 的版本类型支持；Express 不提供 CDC。仍需核对具体版本类型和连接器组合。
- 增量读取基于 SQL Server CDC 变更表与 LSN；已清理的 LSN 不自动跳过，必须提示重新初始化或明确补数方案。
- 第二批额外覆盖 NVARCHAR、DATETIME2、小数、二进制/rowversion 及身份列；rowversion 不作为业务日期解释。未验证的类型明确阻止映射。

## 验收与边界

1. 配置和前置检查测试：Oracle、SQL Server 与现有 PostgreSQL 的隔离、未知版本阻断、凭据脱敏和恢复配置指纹。
2. 实际引擎验证：连接器加载、首次快照、并发写入期间日志衔接、INSERT/UPDATE/DELETE、停止后恢复、进程重启、日志过期和目标不可用。
3. Doris 验证：主键更新收敛、删除不复活、大整数和小数不丢精度、日期时间及大字段完整性。
4. 医院测试表最终使用独立目标，完成全量和增量对账后再宣称可用。上一轮部分目标和失败记录不当作验收成功。
5. 只读源库检查及本地代码工作可独立推进。源库日志/权限/重启、未获范围的测试记录 DML，以及新增网络目的地在具体变更可审阅后另行授权；已批准的 HIS 单地址 TCP1521 规则无需重复申请。
6. 本轮已允许使用专用测试记录，但具体范围尚未提供。未提供前，不对源表进行增删改。

## 执行顺序

第一批按“类型与大表全量修复 → 统一适配器和前置检查 → Oracle CDC → 受控快照与增量恢复验收”推进。第二批增加 SQL Server 2019，之后按实际院内版本验证 2016。现有服务在新实现验收前继续使用固定镜像，不在设计确认阶段变更部署。

方案自检：第一批和第二批边界明确；没有把连接器文档支持当作院内实测通过；没有承诺无日志条件下的 CDC；没有以累计计数代替落盘验证；没有授权未指定范围的源表写入。
