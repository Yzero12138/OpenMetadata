# 医院数据平台 PC 界面与导航重设计方案

日期：2026-10-10
状态：用户已确认整体方案，并批准实施第一批。第二至第四批保留为路线规划；第一批实施与验证结果另行记录。

## 1. 设计目标与已确认约束

按医院内部人员的实际工作组织平台：接入业务库、配置同步、查找资产、维护定义、处理质量问题。让用户通过菜单明确进入哪类工作，每个入口有稳定地址、明确标题和一致操作。

- 交付范围为 PC 浏览器，沿用直接改代码的工作方式。
- Integrate 使用工号和密码登录并作为统一身份入口；平台继续使用既有治理权限。
- 新增、编辑、配置在右侧抽屉中完成；复杂资产详情和可视化编辑器可以使用完整页面。
- 数据源管理、集成任务是独立菜单和页面，归属“数据集成”。
- 沿用 Integrate 已确认的绿色品牌与中文系统字体，把整个工作区的导航、控件和布局统一起来。
- 使用 Taste 默认版的重设计审视原则及 Impeccable 操作型界面规范。Taste 的营销页构图不套用于业务表格和管理表单。
- 复用项目原有核心组件与语义令牌，按页面迁移存量组件；保持可持续同步上游版本的边界。

主要使用场景为数据工程和治理人员的日常维护，以及业务人员的资产查询。这是设计使用场景，实际账号角色仍以当前授权为准。

## 2. 当前结构审视

已检查实际菜单、路由、菜单自定义逻辑、集成页面、质量页面和现有设计记录。集成页面视觉基线参考现有合成验证截图；不把这次源码审视描述为新的线上全站验收。

| 当前现象 | 对使用的影响 | 重设计处理 |
| --- | --- | --- |
| 数据源和集成任务位于同一路径的两个标签 | 两类独立工作缺少独立菜单、页面标题与可分享地址 | 拆成两个菜单、两个页面 |
| 数据集成标题、标签标题、内容标题重复 | 层级冗余，主体内容出现较晚 | 一个页面标题，下接筛选工具栏和列表 |
| “探索、观测、洞察、数据市场”采用不同分类逻辑 | 用户需要先理解产品术语再找功能 | 按数据资产、数据质量、数据治理归组 |
| 集成页绿色操作与存量蓝色导航、标签处理并存 | 全站像多个模块拼接 | 统一品牌选中态、图标、控件及页面间距 |
| 集成工作区同时维护数据源、任务、引擎及表单状态 | 页面职责过多，切换和失败状态互相牵连 | 页面分责，共用 API 和有边界的状态钩子 |
| 数据源连接、目录中的元数据服务、治理工作流含义接近 | 容易将业务数据抽取和元数据采集混淆 | 入口和文案明确区分三种能力 |
| 本体、AI 记忆、批量字段工具与日常功能同等突出 | 低频或专业功能占用日常导航 | 保留能力，通过高级功能配置按需呈现 |

## 3. 组织方式比较

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 按工作领域分组：集成、资产、质量、治理 | 模块职责清楚，菜单稳定，适合混合角色 | 首次调整需要迁移既有导航设置 | 推荐；集成的两项子菜单已确认 |
| 将所有功能平铺为一级菜单 | 常用功能直接可见 | 菜单过长，质量和治理入口难以扩展 | 不作为全站结构 |
| 按角色拆多个独立工作空间 | 可针对不同人简化界面 | 跨角色人员频繁切换，还需要完整角色映射 | 暂不引入；先沿用现有权限 |

## 4. 推荐菜单树

```text
工作台
数据集成
  数据源管理
  集成任务
数据资产
  资产总览
  数据目录
  业务域
  数据产品
  血缘关系
数据质量
  质量检查
  质量问题
  规则模板
  告警管理
数据治理
  业务术语
  分类标签
  指标定义
  治理工作流
  治理统计
知识中心
  知识总览
  知识文章
  文档资料
  归档

底部固定入口：系统管理、个人账户 / 退出
```

导航最多两级。同一时刻优先展开当前功能组，当前子菜单有明确选中态；直接打开详情链接也应自动展开所属组。收起侧栏后仍可通过带文字的浮层选择子菜单，并可使用键盘操作。

“本体浏览器、字段批量维护、AI 记忆”保留为可配置的高级入口：启用后分别归入数据治理或知识中心的二级菜单。菜单隐藏仅负责显示，接口和页面继续检查真实权限。

资产总览保留原数据市场的资产发现及数据产品能力；数据目录负责检索、筛选和列表。两者使用同一资产定义，保留既有个性化配置。若后续整合工作台与资产总览，需单独检查原有组件和入口后再决定，不在首批中删除功能。

“治理统计”承接原数据洞察的资产覆盖、治理指标和平台使用分析；不把该入口描述为医院经营 BI。

## 5. 全局工作区与视觉规范

主结构是固定左侧导航、顶部工具区、主内容区。顶部放当前路径、既有全局搜索、通知和账户入口；菜单只承担导航，内容页承担筛选和操作。避免再增加多标签工作区或第二套重复主导航。

- 左侧展开宽度以 232–248px 为初始设计范围，收起后约 64–72px。实现时通过真实中文菜单和视口检查确定。
- 内容区使用统一边距，建议 24px；列表占满可用宽度，不把管理表格放在窄居中容器里。
- 页面标题建议 22–24px，常规文本和表格 14px，辅助信息 12–13px。使用同一中文系统字体，数字采用等宽数字特性。
- 顶部与页面标题区保持紧凑，主要新建操作位于标题区右侧。筛选区与列表紧接，减少重复说明和大块空白。
- 品牌绿色统一作用于主操作、选中态和链接。侧栏选中项用浅色背景及清楚的文字强调；避免父组和子项同时大面积实色填充。
- 背景、边框、禁用态和状态颜色都通过原生语义令牌定义。错误、告警、成功状态既有文字也有颜色，状态色与品牌色分别表达含义。
- 表格、按钮、输入框、选择器、提示和抽屉复用核心组件；统一图标风格，不再逐页引入新的组件系统。
- 动效仅用于抽屉出现、展开和操作反馈，尊重减少动画设置。全站不加入装饰性动画。
- 优先验证 1366、1440、1920 的 PC 使用场景及 100% / 125% 缩放。低可用宽度通过侧栏收起、抽屉限宽和表格内部滚动处理；不新增手机端流程。
- 默认浅色工作区。保留当前主题能力，并检查既有深色语义映射，避免切换主题后不可读。

## 6. 四种统一页面模板

| 模板 | 结构 | 用途 |
| --- | --- | --- |
| 管理列表 | 面包屑、标题与主操作、筛选工具栏、表格、结果数与分页 | 数据源、任务、术语、规则、成员 |
| 资源详情 | 返回入口、对象标题与状态、概要、关联内容、操作 | 数据资产、任务、业务域、数据产品 |
| 配置抽屉 | 固定标题、分组表单、就地校验、固定操作底栏 | 新增、编辑、授权、连接配置 |
| 可视化工作区 | 紧凑工具栏、主画布、右侧选中对象配置 | 血缘和治理工作流编辑器 |

标签页只用于同一对象的不同视角，例如一个资产的字段、血缘、质量。同一功能域下可以独立管理的对象采用菜单和独立路由。

### 抽屉规则

沿用共享 FormDrawer。数据源表单以现有 720px 宽度为起点，任务创建和编辑以现有 880px / 960px 为起点，并受可用视口宽度限制。打开后保留背后列表的筛选、滚动和选中状态；只有表单内容滚动，保存和取消操作始终可达。

- 表单字段有可见标签、必填标识和中文错误说明。失败保留输入，首次错误获得焦点。
- 保存中阻止重复提交；未保存变更离开时使用抽屉内的明确确认操作。恢复后焦点返回触发按钮。
- 连接密码不回显、不进入 URL；编辑留空继续沿用原密码。
- 关联选择优先使用选择器或当前抽屉内的次级视图；避免叠加多个弹出层。
- 删除等破坏性操作采用行内确认或当前抽屉内确认，不另开居中表单。

## 7. 首批：工作区框架与数据集成

这是第一份可以独立实现和验收的子项目，其余模块按后续批次推进。

### 7.1 数据源管理

页面标题为“数据源管理”，主操作为“新建数据源”。筛选包含名称、数据库类型、源 / 目标和启用状态。列表显示名称、类型与版本、用途、连接摘要、范围、启用状态、连接测试结果及操作。

来源与目标仍复用现有数据源模型及 ID。环境预置源继续显示受管标识，不能通过界面绕过既有编辑限制。测试连接是显式动作，“已保存”和“连接成功”分别呈现。测试结果与定义版本关联；改过配置后旧成功结果不继续代表当前配置。

首批仅使用现有数据字段，不增加业务系统、科室、负责人等尚无存储定义的表单字段。数据源展示名称可由操作人员填写为 HIS、LIS 等实际用途，示例继续标注合成数据。

### 7.2 集成任务

页面标题为“集成任务”，主操作为“新建任务”。列表显示任务名称、来源至目标、同步方式、最近运行状态和时间、目录登记状态及操作。筛选包括名称、来源、目标、同步方式和状态。

新建与编辑继续使用右侧抽屉。配置按基本信息、来源与目标、表选择、字段映射、校验与保存分组。Oracle、SQL Server、MySQL、PostgreSQL 的全量能力按真实连接能力呈现；CDC 仅在现有支持条件满足时提供。

任务名称打开可分享的详情页面。详情展示概要、最近运行、运行记录、恢复条件和目录关联；只有同一任务的内部视角可以使用标签。日志或记录的细节可通过右侧抽屉展开。无可用恢复点时不能显示可执行的恢复动作。

引擎状态放在任务页面的紧凑状态区域；数据源列表无需占据大块引擎展示空间。运行数量、吞吐、时间和目录状态都使用实际返回值；未知与零值明确区分。首批不增加独立调度中心或执行监控菜单。

### 7.3 UI 路由及兼容

建议新增的仅是前端页面路由，服务端 API 路径保持既有定义：

| UI 地址 | 责任 |
| --- | --- |
| `/hospital/integration/sources` | 数据源列表与配置抽屉 |
| `/hospital/integration/tasks` | 集成任务列表与配置抽屉 |
| `/hospital/integration/tasks/:taskId` | 指定任务详情 |
| `/hospital/integration` | 兼容原入口，转到任务列表 |

认证回调先按现有登录流程处理，再执行旧路径兼容；不将登录票据复制到新地址。后退、前进、刷新、门户入口、任务详情直达均要定位正确菜单。

页面拆分职责：数据源页加载数据源；任务页加载任务、可选数据源和引擎状态；任务详情根据 ID 加载指定任务。共用现有 API 客户端与有边界的钩子，不复制凭据处理、保存冲突和运行控制逻辑。不再保留决定主要页面的 activeTab 状态。

首批筛选与分页基于现有接口结果，明确是当前已加载集合，不伪装成服务端全库检索。服务端分页、额外统计和大规模查询属于独立能力扩展。

### 7.4 权限、自定义菜单与失败状态

- 继续执行当前集成管理员权限及服务端校验；本轮不自动授予新角色。
- 已保存的自定义导航使用显式兼容映射：旧集成项迁为父组，新子项继承原显隐设置，保留明确隐藏状态、用户顺序和插件入口。
- 其他模块重组同样迁移保存的导航配置，提供可回退的结构版本，避免新菜单被旧配置静默丢弃。
- 请求可取消，旧响应不覆盖新选择；连接错误、任务错误和引擎不可达分别就地显示并可重试。
- 保存冲突、运行请求结果不确定、账号失效和无权限都有明确状态；登录失效继续交由现有 Integrate 流程处理。

| 第二批 | 资产总览、目录、业务域、产品、血缘 | 搜索列表、对象详情、关系浏览和维护方式统一 |
| 第三批 | 质量检查、问题、规则、告警、术语、分类、指标、工作流 | 检查、定位、维护和处理路径统一；工作流画布右侧配置 |
| 第四批 | 治理统计、知识中心、系统管理及高级入口 | 剩余存量页面统一，设置分类清晰 |
| 各批必须完成 | 中文适配、PC 交互、权限和状态验证 | 所改范围随批验收，不留到最后集中修补 |

元数据服务仍属于系统管理，用于采集表结构、字段和目录信息。SeaTunnel 数据源与任务属于数据集成，用于业务数据同步。首批不合并两套后端连接对象；在需要时提供清楚的相互关联入口。

本方案不新增医院指标计算引擎、数据开发 IDE、调度系统、质量修复引擎或存储平台。现有质量问题处理也不被描述为自动修复业务数据。需要这些业务能力时另立需求，不通过改菜单暗示已经具备。

## 9. 验收标准

第一批至少满足：

1. “数据集成”下有“数据源管理”“集成任务”两个子菜单，各有独立 URL、标题和新建入口，原页面不再显示两类对象之间的切换标签。
2. 旧入口、直达链接、刷新、前进后退、父菜单展开与子菜单高亮一致；原自定义导航和插件入口不会丢失。
3. 数据源的新增、编辑、测试、受管状态及任务的选择来源、校验、保存、运行、停止、恢复、目录关联保持真实可用。
4. 新增和编辑从右侧打开；取消恢复列表状态；错误保留输入；提交中不会重复执行；不同记录不会被旧请求响应覆盖。
5. 三种 PC 宽度及缩放场景下导航清晰，主操作、抽屉底栏可达，长表格仅在表格区域横向滚动。
6. 可键盘完成导航与表单；焦点、标签、对比度和减少动画设置符合共享组件约定。
7. 空结果、加载、失败、无权限、冲突与未知状态分别呈现；中文覆盖新增菜单、字段、说明、状态和错误提示。
8. 使用隔离合成数据完成界面验证；实际院内账号的正向门户登录以授权现场验证为准，不用伪造身份代替。

后续每批复用这些标准，并增加对应原有功能的回归检查。上线、构建和运行验收在实施后记录；本方案本身不代表已经修改或部署界面。
